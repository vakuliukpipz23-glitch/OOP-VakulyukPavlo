# Лабораторна робота №29  
## Тема: Асинхронне читання великих файлів


## Мета роботи
Навчитися ефективно працювати з великими файлами за допомогою асинхронного потокового читання та запису, а також порівняти продуктивність синхронного та асинхронного підходів.


## Завдання
1. Створити консольний проєкт `lab29v1`
2. Реалізувати генератор великого файлу (100 000 – 1 000 000 рядків)
3. Реалізувати асинхронний читач файлу
4. Виконати фільтрацію рядків (логів)
5. Записати результат у новий файл
6. Порівняти продуктивність синхронного та асинхронного підходів


## Формат даних
Файл містить лог-записи у форматі:

2026-04-13T12:00:00 | ERROR | Message 123  
2026-04-13T12:00:01 | INFO  | Message 124  
2026-04-13T12:00:02 | WARN  | Message 125  


## Реалізація

### Генерація великого файлу
Створюється файл `biglog.txt` з 1 000 000 рядків.  
Кожен рядок містить дату, рівень логування та повідомлення.


### Синхронна обробка
- Використовується `StreamReader`
- Рядки читаються послідовно
- Виконується підрахунок ERROR записів


### Асинхронна обробка
- Використовується `ReadLineAsync()`
- Потокове читання без завантаження файлу в пам’ять
- Фільтрація рядків із ERROR
- Запис результату у `errors.txt` через `WriteLineAsync()`


## Порівняння продуктивності
Використано `Stopwatch` для вимірювання часу виконання.

| Тип обробки | Опис | Результат |
|-------------|------|----------|
| Синхронна   | Блокуюче читання файлу | Повільніше при великих файлах |
| Асинхронна  | Потокова обробка | Ефективніше для I/O операцій |


## Результати (приклад)
Sync ERROR count: 332145  
Sync time: 4200 ms  

Async ERROR count: 332145  
Async time: 3100 ms  


## Вихідні файли
- `biglog.txt` — згенерований файл
- `errors.txt` — відфільтровані ERROR записи


## Висновок
У роботі реалізовано асинхронну обробку великого текстового файлу.  
Показано, що асинхронний підхід ефективніший для операцій введення-виведення, оскільки дозволяє обробляти дані потоково без блокування виконання програми.
