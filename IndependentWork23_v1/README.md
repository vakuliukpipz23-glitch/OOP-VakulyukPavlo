1. Поясніть патерн Adapter. Коли його слід використовувати?
Adapter — це структурний патерн, який дозволяє об’єктам із несумісними інтерфейсами працювати разом. Він «перекладає» інтерфейс одного класу в інший, який очікує клієнт.

Його слід використовувати, коли потрібно інтегрувати сторонні бібліотеки або старий код із новою системою, але їхні інтерфейси не збігаються. Adapter дозволяє не змінювати існуючий код, а просто створити проміжний шар, який забезпечить сумісність.

2. Поясніть патерн Facade. Як він спрощує роботу зі складними підсистемами?
Facade — це структурний патерн, який надає простий у використанні інтерфейс до складної підсистеми класів.

Він спрощує роботу тим, що приховує внутрішню складність і взаємодію багатьох класів за одним простим інтерфейсом. Замість того щоб клієнт напряму працював із десятками класів і їх залежностями, він звертається до фасаду, який сам координує виклики всередині підсистеми.

3. Поясніть патерн Proxy. Наведіть приклади різних типів Proxy (Virtual, Protection, Logging).
Proxy — це структурний патерн, який надає замінник іншого об’єкта і контролює доступ до нього.

Virtual Proxy використовується для відкладеної ініціалізації дорогих об’єктів. Наприклад, велике зображення завантажується тільки тоді, коли воно реально потрібне.
Protection Proxy контролює доступ до об’єкта залежно від прав користувача. Наприклад, доступ до адміністративних функцій дозволяється тільки певним ролям.
Logging Proxy додає логування викликів методів без зміни основного класу, фіксуючи, які операції і коли виконувалися.

4. У чому полягає ключова відмінність між Adapter, Facade та Proxy?
Adapter використовується для сумісності інтерфейсів і «перекладу» одного інтерфейсу в інший.
Facade використовується для спрощення складної системи і надання єдиного простого інтерфейсу до неї.
Proxy використовується для контролю доступу до об’єкта або додавання додаткової поведінки при зверненні до нього.
